### 第二阶段：理论学习（约45分钟）

**1. 奖励没有标签，为什么仍然能训练（约15分钟）**

普通ANN训练通常直接比较预测与标签。这里没有“这栋建筑的正确奖励是几分”这样的标签，而是先让奖励影响行为，再比较行为统计。

```text
建筑特征 → 奖励网络 → 建筑奖励
                         ↓
             N04：内部行动概率
                         ↓
             N05：模型期望访问量
                         ↓
                与专家目标比较
                         ↓
             N06：更新奖励网络参数
```

最大熵IRL希望在符合专家统计约束的同时，不额外武断地偏向某一条轨迹；存在多种合理行为时，保留相应的不确定性。它不是把每栋建筑的奖励直接设成访问次数。

标准最大熵IRL原文公式(6)描述的是“专家特征期望−模型特征期望”的似然上升方向。本项目将访问统计差传给奖励网络，但特征行和、内部概率与访问量稳定化都有作者的具体处理；今天不把该实现直接视为标准公式的完整证明。

**2. 外部梯度怎样进入奖励网络（约20分钟）**

对照训练函数：

```python
loss_grad = expert_svf - expected_svf.float()
rewards.backward(-loss_grad)
optim.step()
```

源码先算“专家−模型”，传给`backward`时再取负，因此实际传入的是：

$$
g=d_{\mathrm{model}}-d_{\mathrm{expert}}
$$

`rewards`是多个建筑奖励组成的向量。`backward(g)`将g作为每个奖励输出收到的外部梯度，再沿奖励网络计算参数梯度，不要求先在Python中构造一个标量损失。

对线性奖励模型：

$$
r=Xw+b,\qquad
\nabla_w L=X^\top g,\qquad
\nabla_b L=\sum_i g_i
$$

- X：每行一个状态、每列一个特征。
- w、b：奖励模型的权重和共享偏置。
- g：本轮给每个奖励输出的外部梯度。
- \(\nabla_w L\)、\(\nabla_b L\)：优化器用于调整参数的梯度。

在统计定义相容的标准设定下，模型访问偏少的状态对应奖励的上调方向；访问偏多则相反。网络参数会被多个状态共享，不能据此保证一次更新后每个状态的奖励都独立地按预想增减。

`rewards.detach()`用于内部行动概率分支，使源码不沿这条分支自动反传；原来的`rewards`仍保留奖励网络的计算图。`backward`计算并累积梯度，`optim.step()`才修改参数，`optim.zero_grad()`清除累积梯度。

#### 参考代码

```python
"""
来源：论文官方开源代码 geoirl-official
原始文件：rewards.py、causal_maxent.py
对应模块：Perceptron、irl_causal的外部梯度与参数更新

学习目标：
    调用原始线性奖励模型，观察给定访问统计差怎样更新参数。

说明：
    Perceptron原类保持原样，不添加或删除类内注释。
    专家目标和模型统计是人为给定的教学输入，不是假装运行过IRL。
    rewards.detach()只展示分离结果，本例不执行内部策略和访问量计算。
    SGD用于手算一次参数更新；官方主Notebook中的AdamW配置保持原样。
"""


# 导包
import torch as t


# 1.源代码函数：线性奖励模型，保持官方类原样
class Perceptron(t.nn.Module):
    def __init__(self, n_features,seed=0):
        super().__init__()
        t.manual_seed(seed)
        self.linear = t.nn.Sequential(t.nn.Linear(n_features, 1))

    def forward(self, features):
        return self.linear(features)


# 2.测试主函数：给定统计差，观察梯度和一次参数更新
def main():
    t.set_printoptions(precision=4, sci_mode=False)

    features = t.tensor([[1.0, 0.0], [0.0, 1.0]])
    model = Perceptron(n_features=2)

    # 固定参数初值，便于手算；只设置本例模型，不修改原类。
    with t.no_grad():
        model.linear[0].weight.copy_(t.tensor([[1.0, 2.0]]))
        model.linear[0].bias.fill_(0.5)

    optim = t.optim.SGD(model.parameters(), lr=0.1)
    optim.zero_grad()

    # 两组统计人为给定，单独观察irl_causal中的反向传播部分。
    expert_svf = t.tensor([0.8, 0.2])
    expected_svf = t.tensor([0.3, 0.4])
    rewards = model(features).flatten()
    rewards_for_policy = rewards.detach()
    loss_grad = expert_svf - expected_svf.float()

    print("初始建筑奖励：", rewards.detach())
    print("原奖励是否保留自动求导：", rewards.requires_grad)
    print("分离后的奖励是否需要梯度：", rewards_for_policy.requires_grad)
    print("人为给定的专家目标：", expert_svf)
    print("人为给定的模型统计：", expected_svf)
    print("传给backward的外部梯度：", -loss_grad)

    # 与论文训练函数相同的反向传播语句。
    rewards.backward(-loss_grad)

    print("\n手算权重梯度X.T@g：", features.T @ (-loss_grad))
    print("自动求导权重梯度：", model.linear[0].weight.grad)
    print("手算偏置梯度sum(g)：", (-loss_grad).sum())
    print("自动求导偏置梯度：", model.linear[0].bias.grad)

    # backward只计算梯度，这一步才按梯度更新参数。
    optim.step()
    print("\n更新后的权重：", model.linear[0].weight.detach())
    print("更新后的偏置：", model.linear[0].bias.detach())


# 3.测试
if __name__ == "__main__":
    main()
```

#### 代码与输出说明

- **外部梯度不是奖励标签**：它表达本轮对奖励输出的更新信号，没有给出每栋建筑的“正确奖励”。

- **detach保留数值、切断该结果的自动求导连接**：它不会把原来的rewards也变成无梯度张量；本例不对分离结果做原地修改。
- **梯度与参数更新分开**：backward填充参数的grad，step使用这些梯度修改参数。
- **共享参数影响多个状态**：权重梯度汇总X和g，偏置梯度是g之和，不能仅凭某个状态的残差判断全部参数的变化。
