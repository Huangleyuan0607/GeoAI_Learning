**上海交大张伟楠强化学习课程第 1 讲：强化学习简介 I**：

- **强化学习**

  - **定义**

    - 通过从**交互中学习**来实现目标的计算方法
    - 三个方面：
      - **感知**：在某种程度上**感知环境的状态**
      - **动作**：可以采取动作来**影响状态**或者**达到目标**
      - **目标**：随着时间推移**最大化累计奖励**

  - 强化学习的**交互过程**

    <img src="D:/CCNU/PreLearning_Plan/GeoAI-Learning/rl-geoirl/notes/Screenshot/history/G01/G01_强化学习交互过程.png" alt="G01_强化学习交互过程" style="zoom: 50%;" />

    - 在每一步中`t`，智能体：
      - 获得观察`O_t`
      - 执行动作`A_t`
      - 获得奖励`R_t`
    - 环境：
      - 获得动作`A_t`
      - 给出奖励`R_t`
      - 给出观察`O_t+1`
    - `t`在环境这一步增加

  - 强化学习的**系统要素**

    - **历史**（**History**）：是**观察、动作和奖励**的**序列**
      $$
      H_t = O_1, R_1, A_1, O_2, R_2, A_2, \dots, O_{t-1}, R_{t-1}, A_{t-1}, O_t, R_t
      $$

      - 即，一直到时间`t`为止的所有可观测变量
      - 根据这个历史可以决定接下来会发生什么
        - 智能体选择动作
        - 环境选择观察和奖励

    - **状态**（**State**）：是一种用于确定接下来会发生的事情（**动作、观察、奖励**）的信息

      - 状态是关于历史的函数
        $$
        S_t = f(H_t)
        $$

    - **策略**（**Policy**）：是学习智能体在特定时间的**行为方式**

      - 是从状态到动作的映射

      - **确定性策略**（**Deterministic Policy**）：输入一个状态State，直接输出一个行为Action
        $$
        a = \pi(s)
        $$

      - **随机策略**（**Stochastic Policy**）：输出的是Action的分布，然后在分布中再采集一个Action出来传到环境中去
        $$
        \pi(a|s) = P(A_t = a \mid S_t = s)
        $$

    - **奖励**（**Reward**）：`R_t`和`r(s, a)`

      - 一个**定义强化学习目标**的**标量**，能立即感知到什么是“好”的

  - 强化学习的**目标**

    - 强化学习中，智能体的学习目标为：

      - 在和环境持续的交互中，**最大化期望累计奖励总和**

      $$
      \begin{aligned}
      \max_{\pi} \mathbb{E}_{\pi, \text{Env}} [R_0 + \gamma R_1 + \gamma^2 R_2 + \cdots] \\
      = \mathbb{E}_{\pi, \text{Env}} \left[ \sum_{t=0}^{T} \gamma^t r(s_t, a_t) \right]
      \end{aligned}
      $$

      

    - 在每个时间步，奖励乘上一个衰减因子
      $$
      \gamma \in [0,1]
      $$

**上海交大张伟楠强化学习课程第 3 讲：马尔可夫决策过程 I**：

- **随机过程**

  - 定义：

    - 是一个或多个事件、随机系统或者随机现象随时间发生演变的过程

    $$
    \mathbb{P}[S_{t+1} \mid S_1, \dots, S_t]
    $$

    - **概率论**研究**静态**随机现象的统计规律
    - **随机过程**研究**动态**随机现象的统计规律

- **马尔可夫过程（Markov Process）**

  - 马尔可夫过程是具有**马尔可夫性质**（**下一步的状态分布只基于当前这一步的状态**）的**随机过程**

  - **定义**：

    - 状态`S_t`是马尔可夫的，当且仅当：

    $$
    \mathbb{P}[S_{t+1} \mid S_t] = \mathbb{P}[S_{t+1} \mid S_1, \dots, S_t]
    $$

  - **性质**：

    - 状态从**历史（history）**中捕获了所有相关信息
    - 当状态已知的时候，**可以抛开历史不管**（也就是只基于当前状态）
    - 也就是说，**当前状态是未来的充分统计量**

- **马尔可夫奖励过程**

  - 在马尔可夫过程的基础上加入**奖励函数**和**折扣因子**，就可以得到马尔科夫奖励过程（Markov Reward Process）

  - 主要要素

    - 状态转移`S_t`是马尔可夫的

    $$
    \mathbb{P}[S_{t+1} \mid S_t] = \mathbb{P}[S_{t+1} \mid S_1, \dots, S_t]
    $$

    - 基于每个时间步的状态s，环境产生相应的奖励的`r(s)`，其随机变量记为`R_t`
    - 基于状态序列及其对应的奖励，可以得到序列的汇报

    $$
    G_t = R_t + \gamma R_{t+1} + \gamma^2 R_{t+2} + \cdots = \sum_{k=0}^{\infty} \gamma^k R_{t+k}
    $$

  - 序列回报的形式

    - 问题：为何序列回报需要是如上形式?

    - 需求：我们需要构建**序列之间的全序**，也即是对任意两个序列，**需要有孰好孰坏之分**。

    - 如何做时间衰减？

      - 在每个时间步，奖励乘上一个衰减因子
        $$
        \gamma \in [0,1]
        $$

      - 可以考虑为每一个时间步都有1-γ的概率会直接结束该序列，因此未来的奖励需要打折

      - 该衰减因子也帮助算法收敛

    - 以`γ = 0.5`为例：

      - `G([1, 2, 3]) = 1 x 1 + 0.5 x 2 + 0.25 x 3`
      - `G([1, 2, 3]) < G([3, 2, 1])`

    - 定理：如果希望对于序列有全序，并满足以下性质
      $$
      [a_1, a_2, \cdots] < [b_1, b_2, \cdots] \iff [r, a_1, a_2, \cdots] < [r, b_1, b_2, \cdots]
      $$
      那么序列回报形式只会是上述γ-衰减求和形式

- **马尔可夫决策过程（Markov Decision Process, MDP）**

  - 提供了一套为在**结果部分随机**、**部分在 *决策者的控制*（`A_t`） 下的决策过程建模**的数学框架
    $$
    \mathbb{P}[S_{t+1} \mid S_t] = \mathbb{P}[S_{t+1} \mid S_1, \dots, S_t]
    $$

    $$
    \mathbb{P}[S_{t+1} \mid S_t, A_t]
    $$

  - MDP形式化地描述了一种强化学习的环境

    - **环境完全可观测**
    - 即，**当前状态可以完全表征过程**（**马尔可夫性质**）

  - MDP**五元组**

    - MDP可以由一个五元组表示
      $$
      S, A, P_{sa}, \gamma, r
      $$

      - `S`是**状态**的集合
        - 比如，迷宫中的位置，Atari游戏中的当前屏幕显示
      - `A`是**动作**的集合
        - 比如，向N、E、S、W移动，手柄操纵杆方向和按钮
      - `P_sa`是**状态转移概率**（有时也直接写成`P(·|s,a)`、`P(s'|s,a)`）
        - 对每个状态`s∈S`和动作`a∈A`，`P_sa`是下一个状态在S中的**概率分布**
      - `γ∈[0,1]`是对未来奖励的**折扣因子**
      - `r:SxA→实数集R`是**奖励函数**
        - 有时奖励只和**状态**相关（比如走迷宫：不管你的路径，只管你是否走到出口）

  - MDP的**动态**

    - MDP的动态如下所示：（**状态 -> 动作 -> 奖励 -> 下个状态......**）

      - 从状态`s_0`开始

      - 智能体选择某个动作`a_0∈A`

      - EA智能体得到奖励`r(s_0, a_0)`

      - MDP随机转移到下一个状态`s1~P_s0a0`

      - 这个过程不断进行
        $$
        s_0 \xrightarrow{a_0, r(s_0,a_0)} s_1 \xrightarrow{a_1, r(s_1,a_1)} s_2 \xrightarrow{a_2, r(s_2,a_2)} s_3 \dots
        $$

      - 直到**终止状态s_T出现为止**，或者**无止尽地进行下去**

    - 智能体的总回报为：（即马尔科夫奖励过程）
      $$
      r(s_0,a_0) + \gamma r(s_1,a_1) + \gamma^2 r(s_2,a_2) + \dots
      $$

    - 在大部分情况下，**奖励只和状态有关**

      - 比如，在迷宫游戏中，奖励只和位置相关
      - 在围棋中，奖励只基于最终所围地盘的大小有关

    - 这时，**奖励函数**为`r(s):S→实数集R`

    - **MDP的过程**为
      $$
      s_0 \xrightarrow{a_0, r(s_0)} s_1 \xrightarrow{a_1, r(s_1)} s_2 \xrightarrow{a_2, r(s_2)} s_3 \dots
      $$

    - **累计奖励**为
      $$
      r(s_0) + \gamma r(s_1) + \gamma^2 r(s_2) + \dots
      $$

  - 和动态环境交互产生的数据分布

    - 给定同一个动态环境（即MDP），不同的策略采样出来的(状态-行动)对的分布是不同的

    - **占用度量**（Occupancy Measure）和**策略**
      $$
      \begin{aligned}
      \rho^\pi(s, a) &= \mathbb{E} \left[ \sum_{t=0}^{T} \gamma^t \mathbb{I}(S_t = s, A_t = a) \mid \pi \right], \forall s \in S, a \in A \\
      &= \sum_{t=0}^{T} \gamma^t P(S_t = s, A_t = a \mid s_0, \pi)
      \end{aligned}
      $$
      即计算“**在某个策略 π 下，你平均带着时间折扣，去过某个特定状态-动作对多少次**”

      Indicator function Ⅱ(z)=1 表示事件z发生，否则取0

      - 定理1：和同一个动态环境交互的两个策略元和`π`,得到的占用度量`ρ^π1`和`ρ^π2`满足
        $$
        \rho^{\pi_1} = \rho^{\pi_2} \text{ iff } \pi_1 = \pi_2
        $$
        即**如果一个策略的“打卡记录（占用度量）”和另一个策略一模一样，那这两个策略必定是同一个策略。**

      - 定理2：给定一占用度量`ρ`，可生成该占用度量的唯一策略是
        $$
        \pi_\rho = \frac{\rho(s, a)}{\sum_{a'} \rho(s, a')}
        $$
        即表明**既然“打卡记录”是“习惯”的唯一身份证，那如果给你一份“打卡记录”，你怎么把“习惯”反推出来呢？**

        - **分子 ρ(s,a)**：在状态 s 下，你做**动作 a **的打卡次数。
        - **分母 ∑a′ρ(s,a′)**：在状态 s 下，你做**所有可能动作**的打卡次数之和。
        - 两者相除，就相当于算了个比例（归一化）。这正是**条件概率**：**在状态 s 下，你选择动作 a 的概率。**

    - **状态占用度量**（在t时刻只看状态不看动作）
      $$
      \begin{aligned}
      \rho^\pi(s) &= \sum_{t=0}^{T} \gamma^t P(S_t = s \mid s_0, \pi) \\
      &= \sum_{t=0}^{T} \gamma^t P(S_t = s \mid s_0, \pi) \sum_{a'} p(A_t = a' \mid S_t = s, \pi) \\
      &= \sum_{a'} \sum_{t=0}^{T} \gamma^t P(S_t = s, A_t = a' \mid s_0, \pi) \\
      &= \sum_{a'} \rho^\pi(s, a')
      \end{aligned}
      $$

      - 在t时刻**只看状态不看动作**

      - **大白话**：在策略 π 下，从初始状态 s0 出发，带着时间折扣 γ^t，智能体在第 t 步恰好处于状态 s 的概率之和。

      - 它只关心“在不在状态 s”，不关心做了什么动作。

      - 这里插入了一个
        $$
        \sum_{a'} p(A_t = a' \mid S_t = s, \pi)
        $$
        这其实是**在给定状态 s 下，选择所有可能动作 a′ 的概率之和，它们加起来必然等于 1**（概率论全概率公式）。因为只是乘了 1，所以不影响结果。

    - **策略的累计奖励**
      $$
      \begin{aligned}
      V(\pi) &= \mathbb{E}[r(S_0, A_0) + \gamma r(S_1, A_1) + \gamma^2 r(S_2, A_2) + \cdots \mid s_0, \pi] \\
      &= \sum_{s,a} \sum_{t=0}^{T} \gamma^t P(S_t = s, A_t = a \mid s_0, \pi) r(s, a) \\
      &= \sum_{s,a} \rho^\pi(s, a) r(s, a) = \mathbb{E}_\pi[r(s, a)]
      \end{aligned}
      $$

      - 核心目的：**将“时间序列上的期望回报”等价转换为“状态-动作空间上的期望”。**

      - 第一行：**价值函数的原始定义**
        $$
        \begin{aligned}
        V(\pi) &= \mathbb{E}[r(S_0, A_0) + \gamma r(S_1, A_1) + \gamma^2 r(S_2, A_2) + \cdots \mid s_0, \pi] \\
        
        \end{aligned}
        $$

        - 价值函数 `V(π)` 就是智能体按照策略 `π` 玩下去，把所有时间步的即时奖励（带上折扣 `γ`）加起来，最后求个期望。这是从“**时间 / 轨迹**”的视角来看的。

      - 第二行：**将期望展开为全概率求和**
        $$
        \begin{aligned}
        &= \sum_{s,a} \sum_{t=0}^{T} \gamma^t P(S_t = s, A_t = a \mid s_0, \pi) r(s, a) \\
        \end{aligned}
        $$

        - 这一步是数学上的**期望展开**。期望 E[⋅] 本质上就是“概率乘以取值”的求和。
        - 既然我们要把所有时间步的奖励加起来，我们可以换个角度：**不去看一条条具体的轨迹，而是去遍历所有的状态 s 和动作 a**。
        - 对于某个特定的 (s,a)，只要它在第 t 步出现了，就会产生奖励 r(s,a)。它出现的概率是 P(St=s,At=a)，加上时间折扣 γ^t，把所有时间和所有 (s,a) 组合起来双重求和。
        - **蓝色高亮部分**：正是 (s,a) 在第 t 步发生的概率乘以折扣。

      - 第三行：**代入占用度量，完成升华**
        $$
        \begin{aligned}
        &= \sum_{s,a} \rho^\pi(s, a) r(s, a) = \mathbb{E}_\pi[r(s, a)]
        \end{aligned}
        $$

        - 直接把 `ρ^π(s,a)` 替换进去，就得到了第三行的前半部分：
          $$
          \sum_{s,a} \rho^\pi(s, a) r(s, a)
          $$

        - 这个求和又可以简写为一个期望
          $$
          \mathbb{E}_\pi[r(s, a)]
          $$
          ，意思是：**在占用度量（即智能体长期访问状态-动作的概率分布）下，奖励函数的期望值。**

#### 学习笔记

**论文摘要、Figure1及§2.1–2.2相关内容**：

- **论文摘要**

  - **部分名词解释**
    - **多维聚类**：一类**无监督学习方法**。它把每个对象用**多个特征或变量**来描述，**构成一个“多维向量”**，然后根据这些对象**在多维特征空间中的相似程度**，把它们分成若干组，也就是“簇”。**同一簇内的对象在多个维度上尽量相似**，**不同簇之间尽量不同**。
      - 通俗解释：用**多个特征**给城市地点或出行行为画相似画像，再**把画像相似的对象归为一类**，最后在**同一类内部**共享和传播建筑、出行等信息，从而把两套对不上的数据连接起来。
  - **论文目的**
    - **在真实出行数据不够、而且和城市建筑数据对不齐时，怎么生成更像真人的虚拟出行轨迹。**
      - 生成轨迹的方法：给虚拟智能体一个出发地和目的地，让它**按照模型学到的决策规则走出一条路径**。
  - **使用数据**
    - **耶路撒冷**的两个数据集
      - 一个**基于 GPS 的出行调查数据集**
      - 一个**包含全部建筑物的 GIS 数据集**
  - **核心方法**
    - **用图神经网络学“奖励函数”**，从**全局数据模式**或**局部邻域结构中**学习。（而对于**线性方法和MLP**而言**转移概率主导行为**）
  - **评价指标**
    - 在缺乏普遍接受的评价方法的情况下，使用**聚合性能指标**而非单条轨迹相似度来评估轨迹。比如整体出行分布、热点区域、流量模式等是否接近真实。
      - 本文中，**聚合性能指标**指：把生成轨迹和真实轨迹分别汇总成**统计分布或流量**，再比较两组数据的整体特征是否接近，而不是逐条寻找对应轨迹、比较路线是否相似。
        - **统计分布**：**不同情况各占多少**。假设有 100 条轨迹，统计每条轨迹的总距离（根据距离大小分成3个区间），两组数据接近，就说明生成轨迹较好地保留了真实数据的特点。
        - **流量**：**某种移动发生了多少次**。把所有轨迹中的移动次数累计起来，就是类型之间的**出行流量**。
      - 本文通过**轨迹距离**、**停靠数量**、**活动范围的分布**，以及**土地利用类型间的出行流量**，评价生成轨迹是否保持真实数据的总体出行规律。这种评价能够反映整体统计真实性，但不能据此证明每条生成轨迹都合理。
  - **论文结论**
    - **GNN 学到的奖励和建筑面积关系更强**。意思是，模型学到的“哪里更值得去、哪里更容易发生出行”，和建筑密度、建筑规模这些城市活动特征更吻合。奖励变化后，也会影响地点之间的转移概率。
    - **基于 GNN 的奖励函数能提升模拟轨迹的真实性**，比线性方法和 MLP 更好，但仍然需要进一步完善。

- **Figure1**

  - 通过这张图，可以理解论文实验的全流程：
    - **1、构建特征矩阵**：把各建筑的面积、高度、距市中心距离、用途等特征做成特征矩阵，并通过多维聚类把 GPS 访问热度传播到未观测建筑。
    - **2、得到专家 ESVF**：从真实 GPS 轨迹中聚合各建筑的访问次数，得到专家期望状态访问频率（Expert’s ESVF）。
    - **3、训练循环**：
      - 将特征矩阵输入奖励函数，输出每栋建筑的奖励；
      - 奖励和状态转移矩阵结合，计算局部动作概率，得到中间策略；
      - 根据中间策略、初始状态、终止状态和状态转移矩阵，计算模型 ESVF；
      - 将模型 ESVF 与专家 ESVF 比较，计算损失梯度；
      - 用梯度更新奖励函数权重；
      - 重复上述过程，直到损失收敛。
    - **4、生成轨迹**：
      - 收敛后，用最终奖励和状态转移矩阵得到最终策略；
      - 从初始状态开始，根据最终策略逐步采样下一个地点，直到到达终止状态；
      - 生成一条模拟轨迹。

- **§2.1–2.2相关内容**

  - **2.1 学习框架**

    - **2.1.2 特征矩阵**

      - 每个特征分别聚类，让每栋建筑获得多个聚类标签；然后计算每个“特征-聚类组合”的平均访问次数，再把这个平均值传播给同组合中未被 GPS 记录的建筑。这样，GPS 出行热度就被“借”给了那些画像相似但未被观测的建筑，从而缓解了数据不完整的问题。

    - **2.1.3 转移矩阵**

      - 先按原始得分高低筛选出前 10% 的强连接，再对这些强连接做行归一化，按原始得分比例分配概率，最终得到转移矩阵。

      - **简单重力得分（SGS）**：借鉴了物理学中的万有引力定律，用来衡量两栋建筑之间发生出行转移的吸引力或概率。通俗地说，它的核心逻辑是：一栋建筑体量越大、距离越近，人们越容易在它们之间移动。公式：
        $$
        \mathrm{SGS}_{ij} = \frac{V_i}{D_{ij}^{2}}, \quad i \neq j
        $$
        ，即距离越近，或起点建筑面积（或是体积）越大，SGS就越高。但当 i=j 时，得分为 0，即建筑不能原地转移。

    - **2.1.4 初始状态和终止状态**

      - 因为前面用多维聚类把建筑变成了“聚类隶属度向量”，状态空间已经不再是具体的物理建筑，而是属性组合。这样一来，就不能像以前那样直接从 GPS 数据里找出“某个人从哪栋楼出发、到哪栋楼结束”，所以论文只能换一种方式来处理初始状态和终止状态。
      - **聚类隶属度向量**：用一个向量记录一栋建筑在各个特征维度上分别属于哪一类。它把具体的建筑抽象成了“属性组合”，让原本没有出行记录的空白建筑，也能通过属性相似性获得估计的访问热度，从而把不完整的状态空间补齐。
      - **视为轨迹情境化的问题**：因为它把“剥离具体情境（训练）→ 学习抽象动态 → 重新情境化（生成）”作为一个完整过程来对待。训练时剥离情境是为了应对数据缺失，生成时重新情境化是为了让轨迹落到具体的楼上。所以，它既叫“剥离情境”，也叫“重新情境化”，合起来就是“轨迹情境化问题”。
      - **"在本应用中，我们选择无信息的初始状态和终止状态。我们将研究区内所有建筑物随机指定为初始状态，并将研究区内所有居住和混合用途建筑物指定为终止状态。"**：这是训练阶段的做法，在生成阶段起终点都会设置成家。

    - **2.1.5 奖励的非线性**

      - MaxEntIRL 默认的奖励函数是线性的，但城市地理空间动态很复杂，线性可能不够用。所以论文实现了四种奖励函数模型来对比，看看非线性模型，尤其是图神经网络，能不能学得更好。
      - 这段是在为后续实验做铺垫，说明论文用了哪四种奖励函数、它们各自有什么特点、为什么要用图神经网络，以及如何通过对比来验证非线性奖励尤其是图结构奖励的优势。

    - **2.1.6 收敛性与拉普拉斯矩阵**

      - 这一段是在解决 MaxEntIRL 训练时“算着算着就崩了”的问题。论文用拉普拉斯矩阵作为“稳定器”，控制了迭代过程中主特征值的增长，成功稳定了 ESVF 的计算。而且他们发现，图神经网络（GNN）因为自带图结构信息，初始主特征值更高，所以比线性模型和 MLP 收敛得更快、学得更好。
      - **拉普拉斯矩阵**：L=D−A，就是图论里的“差异测量仪”和“平滑器”。它衡量一个节点和它邻居之间的差异，能控制数值的放大倍数。在论文里，它被用来限制 MaxEntIRL 迭代计算时的特征值，防止计算发散，从而稳定并加速 ESVF 的收敛。
        - 作用：**衡量每个节点和它邻居之间的“差异”**。

    - **图3. 使用拉普拉斯矩阵稳定期望状态访问频率计算的伪代码**

    - 为了防止智能体在回家前漫无目的地乱逛，论文用 Kaplan-Meier 生存分析从真实数据中提取了“每一步继续走 vs 回家”的概率（生存概率与终止概率）。在生成轨迹的每一步，智能体都要以一定的终止概率选择直接回家，或以生存概率继续前往其他建筑。这保证了生成的轨迹长度符合真实人类出行的长尾分布（大多是短途，极少是长途），最终得到 6567 条有效轨迹用于评估。
    - **"这里我们使用特定的状态，是为了生成一条在特定点开始并结束的唯一轨迹，从而对该过程进行重新情境化，而不是上文所讨论的用于学习的一般性定义。"**：这里就是生成阶段的情景化，与训练阶段将建筑物抽象成特征组不同，生成阶段的建筑物就回归成具体实际的实体了。
    - **“在每一步中，我们将终止概率赋予智能体的家庭，并将生存概率均匀分配给其余建筑物。这组概率与相应的转移概率以及来自 IRL 的奖励相乘，从而得到用于采样的最终策略。由此，生成的轨迹具有与经验数据相似的长尾分布，范围从 2 到 25（我们将在第3.4节中进一步评估所生成轨迹的质量）。”**：
      - 防止生成轨迹过长的办法：在生成轨迹的每一步，论文都会做这样一套计算：
        - 给“家”赋予终止概率：如果这一步算出来的终止概率是 0.4，那么智能体有 40% 的概率直接选择回家。
        - 给“其他所有建筑”均匀分配生存概率：如果生存概率是 0.6，那么剩下的 60% 概率，会被平均分给除了家以外的所有建筑（假设有 100 栋，每栋分到 0.6 / 100）。
        - 乘以转移概率和奖励：把上面这组概率，乘以对应的转移概率（来自 SGS 矩阵）和IRL 学到的奖励。
        - 得到最终策略：归一化后，智能体根据这个概率分布，采样下一个地点。
      - **图4. 使用生存分析从经验轨迹数据集中提取的折扣因子**
        - 这张图就是真实人类出行长度的“体检报告”。横轴代表去了多少个地方，纵轴代表还有多少人坚持在走。论文通过红点（生存概率）提取出了这种“走到某一步就越来越想回家”的规律，并在生成轨迹时强制智能体按这个规律决定是否回家，从而生成长度极其逼真的轨迹（大多是2~5个点，极少超过10个点）。

```python
"""
来源：geoir1-official（原论文官方开源代码库提取）
原始文件：transitions.py
函数名：simple_gravity

描述：
    本函数是从 geoir1-official 源码中单独提取出来的转移矩阵构建模块。
    用于根据建筑物的坐标和建筑面积，基于简单重力模型（Simple Gravity Score, SGS）计算建筑物之间的初始转移概率矩阵。
    数学公式为：SGS_ij = V_i / D_ij^2（当 i ≠ j），对角线元素为 0。其中 V_i 为起点建筑 i 的建筑面积，D_ij 为建筑 i 与 j 之间的欧几里得距离。

    实现细节：
        参数 beta 硬编码为 2，对应公式中的距离平方。
        使用 PyTorch 的 cdist 计算坐标间的欧几里得距离，并取 beta 次方。
        将对角线距离（0）替换为 1e5，避免除零错误。
        计算 scores = 建筑面积 / 距离^2，并将对角线置 0。
        对 scores 进行行归一化（每行除以该行总和），得到每行和为 1 的转移矩阵。

    注意：
        原函数名 simple_gravity 直接对应论文中的简单重力得分（SGS），但源码中 beta 固定为 2，且未提供可配置参数。
        返回的转移矩阵为稠密矩阵，后续论文中会进行稀疏化至 10% 密度以减轻计算负载。

参考文献：
    - 论文：Generating geospatial trajectories with incomplete data using graph inverse reinforcement learning
    - 代码仓库：https://doi.org/10.6084/m9.figshare.29554394
"""


# 导包
import numpy as np
import pandas
import pandas as pd
import torch


# 1.定义函数，实现：简单重力模型
# 参数buildings:一个包含建筑物信息的 pandas DataFrame（需包含 x, y 坐标和 floorspace 建筑面积）
def simple_gravity(buildings: pd.DataFrame):
    """
    计算建筑物之间的转移概率矩阵，基于简单重力模型（Simple Gravity Score, SGS）
    参数：
        buildings: 一个包含建筑物信息的 pandas DataFrame，需包含 x, y 坐标和 floorspace 建筑面积
    返回值：
        transition: 一个形状为 (N, N) 的转移概率矩阵，表示建筑物之间的转移概率
    """
    # 1.定义距离衰减参数 beta
    beta = 2        # 对应公式 SGS_ij = V_i / (D_ij)^beta 中的指数。论文中 beta = 2，即距离的平方

    # 2.从 DataFrame 中提取 "x" 和 "y" 两列数据
     # 形状为 (N, 2)，N 为建筑物总数。每一行是一个建筑的二维坐标
    coor = torch.tensor(buildings.loc[:, ["x", "y"]].to_numpy())

    # 3.提取 "floorspace" 列（建筑面积）
     # 形状为 (N,)。对应公式中的 V_i（起点建筑的体积/面积）
    vol = torch.tensor(buildings.floorspace.to_numpy())

    # 4.计算所有建筑物两两之间的欧几里得距离（p=2）
    # 形状为 (N, N) 的矩阵。然后再取 beta 次方（即平方），对应公式中的 D_ij^2
    distance = torch.cdist(coor, coor, p=2).pow(beta)
    # 当距离为0时（即自己到自己，或坐标完全相同的情况），替换为1e5，避免除零错误
    distance[distance == 0] =1e5

    # 5.计算SGS得分，核心公式计算：SGS_ij = V_i / D_ij^2
    # 利用 PyTorch 的广播机制，vol (N,) 会广播到 distance (N, N) 的每一行
    # 结果 scores 的形状为 (N, N)，scores[i][j] 表示从 i 到 j 的原始重力得分
    scores = vol.div(distance)      # score = vol / distance = V_i / D_ij^2

    # 6.将矩阵的对角线元素置为 0
    # 对应公式中：当 i = j 时，SGS_ij = 0（即建筑不能转移到自身）
    scores = scores.fill_diagonal_(0)

    # 7.行归一化：将原始得分转化为转移概率
    # torch.sum(scores, 1) 对每一行求和，view(-1, 1) 将其变为 (N, 1) 的列向量
    # scores.div(...) 将每一行的每个元素除以该行的总和，使得每一行的概率之和为 1
    transition = scores.div(torch.sum(scores, 1).view(-1, 1))

    return transition       # 最终返回合法的状态转移矩阵 transition


# 2.定义主函数，用于：测试simple_gravity函数
# 核心逻辑：构造一个只有3栋建筑的极简合成数据集，手动算出理论上的转移概率，然后断言（assert）程序计算的结果与手算结果一致。
def main():
    # 构造一个包含3栋建筑的合成 DataFrame
    # x, y 是坐标（都在x轴上），floorspace 是建筑面积
    # 建筑0: 坐标(0,0), 面积10；建筑1: 坐标(1,0), 面积20；建筑2: 坐标(3,0), 面积30
    buildings = pd.DataFrame({
        "x": [0.0, 1.0, 3.0],
        "y": [0.0, 0.0, 0.0],
        "floorspace": [10.0, 20.0, 30.0],
    })

    # 调用 simple_gravity 函数，计算转移矩阵
    transition = simple_gravity(buildings)

    # 将 PyTorch 张量转换为 NumPy 数组，方便后续用 numpy 的测试工具进行断言和打印。
    values = transition.detach().cpu().numpy()      # .detach() 断开计算图，.cpu() 移动到CPU，.numpy() 转为数组

    # 断言测试部分
    # 1. 验证矩阵形状是 (3, 3)
    assert values.shape == (3, 3)
    # 2. 验证矩阵中所有元素都是有限数（没有 NaN 或 Inf，验证 1e5 替换 0 的操作有效）
    assert np.isfinite(values).all()
    # 3. 验证所有概率都是非负数
    assert (values >= 0).all()
    # 4. 验证对角线元素全为 0（建筑不能转移到自身）
    np.testing.assert_allclose(np.diag(values), 0.0, atol = 1e-8)
    # 5. 验证每一行的概率之和为 1（行归一化正确）
    np.testing.assert_allclose(values.sum(axis = 1), 1.0, atol = 1e-8)

    # 手动计算验证（第一次）
    # 从建筑0出发，手动计算理论概率：
    # 注意：根据 simple_gravity 的代码，scores[i,j] = vol[j] / distance[i,j]^2
    # 建筑0到建筑1：距离=1，分数 = 20 / 1^2 = 20
    # 建筑0到建筑2：距离=3，分数 = 30 / 3^2 = 30/9 = 10/3
    # 总分 = 20 + 10/3 = 70/3
    # 归一化：建筑0->1 概率 = 20 / (70/3) = 60/70 = 6/7
    #        建筑0->2 概率 = (10/3) / (70/3) = 10/70 = 1/7
    manual_before = np.array([0.0, 6.0 / 7.0, 1.0 / 7.0])

    # 断言：程序计算出的第一行（建筑0出发）与手算结果一致
    # 参1：程序计算出的第一行（建筑0出发）；参2：手算结果；参3：相对容差；参4：绝对容差
    np.testing.assert_allclose(values[0], manual_before, rtol = 1e-6, atol = 1e-8)

    # 手动计算验证（第二次：改变目的建筑面积）
    # 只改变目的建筑2的面积（30 -> 60），其他条件保持不变
    changed = buildings.copy()
    changed.loc[2, "floorspace"] = 60.0

    # 重新计算转移矩阵
    values_after = simple_gravity(changed).detach().cpu().numpy()

    # 手动计算新的概率：
    # 建筑0到建筑1：分数 = 20 / 1^2 = 20
    # 建筑0到建筑2：分数 = 60 / 3^2 = 60/9 = 20/3
    # 总分 = 20 + 20/3 = 80/3
    # 归一化：建筑0->1 概率 = 20 / (80/3) = 60/80 = 3/4
    #        建筑0->2 概率 = (20/3) / (80/3) = 20/80 = 1/4
    manual_after = np.array([0.0, 3.0 / 4.0, 1.0 / 4.0])

    # 断言：改变面积后，第一行的结果与新的手算结果一致
    np.testing.assert_allclose(values_after[0], manual_after, rtol = 1e-6, atol = 1e-8)

    # 断言：建筑2面积增加后，从建筑0转移到建筑2的概率应该变大（1/4 > 1/7）
    assert values_after[0, 2] > values[0, 2]

    # 打印输出部分
    print("合成输入：")
    print(buildings.to_string(index = False))

    print("原转移矩阵：")
    print(values)

    print("各行之和：", values.sum(axis=1))

    print("第一行修改前：", values[0])
    print("第一行修改后：", values_after[0])

    print("与手算的最大误差：",np.max(np.abs(values[0] - manual_before)), np.max(np.abs(values_after[0] - manual_after)))

    print("上述断言全部通过！")


# 3.测试
if __name__ == "__main__":
    main()
```
